# سفارش‌یار ۲ — ظاهر جدید و اشتراک عکس

این بسته سورس نسخهٔ ۲ اندروید است. برنامهٔ بومی Java است و اطلاعات شرکت‌ها و سفارش‌ها را در SQLite روی گوشی نگه می‌دارد.

## تغییرات این نسخه

- بازطراحی صفحهٔ اصلی با زمینهٔ روشن، کارت شرکت با طیف سبز تیره، کارت‌های سفید، آیکون‌های خطی، ارقام فارسی و دکمه‌های گرد.
- نمایش تعداد اقلام و مجموع کارتن‌ها، انتخاب تاریخ با دکمه‌های افقی و انتخاب شرکت در پنجرهٔ اختصاصی.
- فرم‌های جدید با فیلدهای کادردار و دکمهٔ ثابت ثبت در پایین؛ حفظ متن فرم هنگام چرخش صفحه.
- گزینه‌های ویرایش و حذف زیر دکمهٔ سه‌نقطهٔ هر کالا؛ حذف همچنان تأیید می‌خواهد.
- تصویر سفارش با سربرگ نام شرکت، ویزیتور، تلفن، قیمت‌ها و شمارهٔ صفحه؛ رنگ‌های هماهنگ با برنامه.
- نام فایل عکس از نام شرکت ساخته می‌شود؛ نمونه: «شرکت پخش بهار_1405-07-04_صفحه-01.png».
- پیش‌نمایش صفحات قبل از ذخیره یا ارسال؛ اشتراک‌گذاری همین صفحه یا همهٔ صفحات از طریق انتخاب‌گر اندروید.
- متن اصلی رابط حداقل ۲۰sp است. متن بدنهٔ گزارش ۲۰ واحد با رندر دوبرابر و تصویر ۱۰۸۰ × ۲۴۰۰ پیکسل است؛ فهرست بلند چندصفحه‌ای می‌شود.

## به‌روزرسانی مخزن فعلی شما با گوشی

گردش‌کار فعلی شما ZIP را استخراج و از پوشهٔ `android-source/OrderBook` می‌سازد. این ساختار در نسخهٔ جدید حفظ شده است.

1. فایل جدید `OrderBook-Android.zip` را دانلود کنید. اگر مرورگر عددی به نام اضافه کرد، نام را دقیقاً به همین نام برگردانید.
2. در صفحهٔ اصلی مخزن GitHub، `Add file → Upload files` را بزنید.
3. همین ZIP جدید را با نام دقیق قبلی بارگذاری و `Commit changes` کنید تا نسخهٔ قدیمی جایگزین شود.
4. در `Actions` جدیدترین اجرای `Build Android APK` را باز کنید. دستور ساختی که قبلاً روی مخزن شما موفق شده نیاز به تغییر ندارد.
5. بعد از موفقیت، از `Artifacts` فایل `OrderBook-APK` را دانلود و استخراج کنید. فایل نصب `app-debug.apk` است.

نسخهٔ این بسته `versionCode=2` و `versionName=2.0` است. شناسهٔ برنامه و دیتابیس با نسخهٔ قبلی یکسان‌اند و Store.java تغییر نکرده است. برای نصب روی نسخهٔ قبلی بدون حذف داده، امضای هر دو APK نیز باید یکسان باشد. ساخت‌های debug روی اجراکننده‌های جداگانه ممکن است کلید یکسانی نداشته باشند. اگر گوشی خطای تداخل امضا یا نصب‌نشدن داد، برنامهٔ قبلی را حذف نکنید؛ حذف برنامه اطلاعات آن را پاک می‌کند. ابتدا موضوع امضا و حفظ اطلاعات را بررسی کنید. این بسته کلید خصوصی نسخهٔ قبلی شما را در اختیار ندارد.

## ارسال در ایتا

1. شرکت و در صورت نیاز تاریخ سفارش را انتخاب کنید.
2. پایین صفحه روی «عکس و ارسال» بزنید.
3. در پیش‌نمایش، «اشتراک‌گذاری عکس» یا «اشتراک همهٔ عکس‌ها» را بزنید.
4. در فهرست برنامه‌های گوشی، ایتا را انتخاب کنید و گیرنده را خودتان تعیین کنید.

ارسال خودکار انجام نمی‌شود. نصب ایتا و پشتیبانی نسخهٔ نصب‌شده از دریافت تصویر لازم است. اگر ایتا برای ارسال چند عکس نمایش داده نشد، «اشتراک همین صفحه» را بزنید. راه جایگزین: «ذخیرهٔ این عکس» و انتخاب فایل ذخیره‌شده از داخل ایتا. ممکن است پیام‌رسان نام یا فشرده‌سازی تصویر ارسالی را تغییر دهد؛ نام فایل ایجادشده و سربرگ داخل تصویر نام شرکت را دارند.

گزارش‌ها از طریق FileProvider و دسترسی موقت فقط‌خواندنی اشتراک‌گذاری می‌شوند؛ دیتابیس در مسیر اشتراک قرار ندارد. نسخهٔ حاضر پشتیبان‌گیری و بازیابی دیتابیس ندارد.

## جزئیات ثبت سفارش

نام کالا، خرید و مصرف به تومان، درصد اختلاف نسبت به خرید، تسویه به روز، تعداد کارتن کامل، تاریخ تحویل شمسی و توضیحات نگهداری می‌شوند. درصد برابر است با `(مصرف − خرید) ÷ خرید × ۱۰۰`؛ مثال خرید ۱۰۰٬۰۰۰ و مصرف ۱۲۵٬۰۰۰ → ۲۵٪. تاریخ ثبت هنگام ویرایش تغییر نمی‌کند. تاریخ تحویل پیش‌فرض از تاریخ سیستم گرفته می‌شود. ارقام فارسی، عربی و انگلیسی پذیرفته می‌شوند و اعداد هنگام تایپ جداکنندهٔ هزارگان دارند.

## ساخت از سورس استخراج‌شده

Android 7 / API 24 به بالا. نیاز ساخت: JDK 17، Gradle 8.9، Android SDK 35، AGP 8.7.3. وابستگی AndroidX Core 1.15.0 برای اشتراک فایل استفاده شده است.

```sh
gradle :app:testDebugUnitTest :app:assembleDebug
```

خروجی: `app/build/outputs/apk/debug/app-debug.apk`.

گردش‌کار داخل `.github/workflows/build.yml` برای حالتی است که خود فایل‌ها و پوشه‌های استخراج‌شده در ریشهٔ مخزن باشند. مخزن فعلی شما که ZIP را استخراج می‌کند می‌تواند دستور ساخت موفق قبلی را نگه دارد.

## وضعیت بررسی

آزمون‌های SQL و بررسی XML در محیط تهیهٔ فایل اجرا شده‌اند. آزمون‌های جدید JUnit برای نام فایل فارسی، حذف جداکنندهٔ مسیر، محدودیت طول Unicode، فرمول درصد و اعداد فارسی اضافه شده‌اند و با دستور بالا اجرا می‌شوند. این آزمون‌های Java و ساخت APK در محیط تهیهٔ بسته اجرا نشده‌اند، چون Android SDK و کامپایلر Java در دسترس نیستند.

اجرای روی گوشی، بررسی تصویری رابط جدید و تحویل عکس به ایتا هنوز باید روی دستگاه انجام شوند. این فایل یک APK تست‌شده نیست.

پیش از استفادهٔ اصلی بررسی کنید: ثبت/ویرایش/حذف، نام شرکت بلند، فونت بزرگ گوشی، چرخش فرم، تصویر چندصفحه‌ای، ذخیره با نام فارسی، ارسال یک عکس و چند عکس به ایتا، و خوانایی نام کالا و توضیحات بلند در خروجی.
